# claims-check - 주의 표현 점검 (06번 파일)

> `{out}` = 이번 프로젝트의 결과 폴더 `outputs/<제품명>_<날짜>/` 입니다. 단독 실행할 때는 가장 최근 폴더를 쓰고, 둘 이상이라 모호하면 먼저 묻습니다. (`skills/README.md` 참고)

문구가 **"무엇을 하는 제품이라고 말하는가"** 에 따라 규제 해석이 달라질 수 있습니다. 이 스킬은 위험 신호를 표시해 사람이 전문가와 확인할 목록을 만들어 줍니다.

> **참고용이며 법률 자문이 아닙니다.** 규정은 나라와 카테고리마다 다르고 바뀝니다. 최종 문구는 시행 시점의 공식 안내와 전문가(변호사, 규제 컨설턴트)로 확인하세요.

## 입력값
- `{out}/04_pdp_draft.md`, `{out}/05_shortform.md`의 문구 목록
- `brand.md`: 우리 제품 사실, 증빙 보유 여부, **판매 국가, 카테고리**, "써도 되는지 궁금한 표현"

## STEP 0 - 지원 범위 확인 (가장 먼저)
`brand.md`의 판매 국가와 카테고리를 읽고, 없으면 묻는다.

| 국가 x 카테고리 | 점검 방식 |
|---|---|
| **미국 x 화장품**(스킨케어, 립케어, 헤어, 바디 등 외용 미용 제품) | **상세 점검**: 아래 A~G 전체 |
| 그 밖의 국가 또는 카테고리 (식품, 건강기능식품, 의료기기, 어린이용품, 전기제품, 다른 나라 화장품 등) | **일반 점검**: C, D, E, F만 적용. 해당 국가, 카테고리의 고유 규정은 이 스킬에 수록되어 있지 않으므로 **`[확인 필요]`로 표시하고 전문가 확인 질문을 만든다** |
| 위 어느 쪽이든 사용자가 **공식 가이드 URL**을 준 경우 | 해당 URL을 읽어 그 기준과 문구를 대조하고, 근거는 `[사실: URL]`로 적는다 (읽지 못하면 `ACCESS FAILED`) |

- 일반 점검인 경우 파일 상단에 "이 제품의 국가, 카테고리는 상세 점검 범위 밖입니다. 규정별 판단은 포함하지 않았습니다"를 적는다.
- 식품, 건강기능식품, 의료기기, 어린이용품은 효능, 인증, 표시 규정이 엄격한 경우가 많다는 점을 알린다 `[확인 필요]`. 구체 규정을 지어내지 않는다.

## 점검 분류

| 분류 | 위험 신호 예시 | 처리 | 적용 |
|---|---|---|---|
| **A. 질환 치료, 예방** | treat/cure/prevent/heal + 질환명(eczema, rosacea, dermatitis, acne 치료) | 삭제. 피부 상태가 아니라 느낌과 사용 장면으로 바꾼다 | 미국 화장품 |
| **B. 피부 구조, 기능 변화** | repair cells, regenerate, stimulate collagen, penetrates deep, permanently | 완곡한 표현으로 바꾸고 증빙 여부를 표시 | 미국 화장품 |
| **C. 근거가 필요한 주장** | clinically proven, dermatologist recommended/tested, "86% 증가"류 수치, "in 1 hour"류 시간, "#1", 비교 우위 | 증빙(기관, 대상 수, 기간, 지표)이 `brand.md`에 있을 때만 사용. 없으면 삭제 | **공통** |
| **D. 안전 단정** | no irritation, non-irritating, hypoallergenic, safe for all, no side effects | 삭제 또는 사실 서술. 사용 전 확인(패치 테스트 등) 안내 추가 | **공통** |
| **E. 후기와 협찬** | 가짜, 매수 후기, 협찬 미표기, 경쟁사 후기 인용 | 우리 고객의 실제 후기만. 협찬, 체험단은 표시(`#ad` 등) | **공통** |
| **F. 전후 사진, 영상 연출** | before/after 편집, 연출된 효과 | 동일 조건 촬영과 증빙이 없으면 사용하지 않는다 | **공통** |
| **G. 표시 사항** | 전성분, 알레르겐, 용량 표기 누락 | 라벨, 상품 페이지 표시 사항은 규정 확인 대상으로 목록화 | 미국 화장품 (그 외는 확인 필요) |

## 실행 절차
1. 04, 05의 모든 문구를 **한 줄씩** 표에 올린다: 문구 / 위치 / 분류 / 위험도(높음, 중간, 낮음, 해당 없음) / 이유 / 안전한 대안 문구 / 필요한 증빙.
2. `brand.md`의 **"써도 되는지 궁금한 표현"** 을 맨 앞에서 별도로 다룬다. 각 표현에 대해 분류와 위험도, 쓸 수 있는 조건, 대안을 답한다. 확답이 불가능하면 "전문가 확인 필요"라고 말한다.
3. **위험도 높음**은 맨 위에 모아 보고한다.
4. `brand.md`의 증빙이 `없음`인 항목은 C, D 분류 문구를 **자동으로 `삭제 권장`** 으로 둔다.
5. 경쟁사가 쓰는 문구라고 해서 안전한 것은 아니다. 경쟁사 문구는 **참고 사례로만 표시**한다.
6. 마지막에 **전문가에게 확인할 질문 5개**를 만든다. 일반 점검이면 국가, 카테고리의 표시, 광고 규정 확인을 질문에 포함한다.

## 작성 원칙
- 없는 규정을 만들어 내지 않는다. 확실하지 않으면 "확인 필요"로 표시하고 공식 출처를 안내한다.
- 점검은 **문구와 근거의 일치**를 본다. 효능이 좋다는 것과 말해도 된다는 것은 다르다.
