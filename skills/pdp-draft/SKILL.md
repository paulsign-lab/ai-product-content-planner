# pdp-draft - 상세페이지 초안 (04번 파일)

> `{out}` = 이번 프로젝트의 결과 폴더 `outputs/<제품명>_<날짜>/` 입니다. 단독 실행할 때는 가장 최근 폴더를 쓰고, 둘 이상이라 모호하면 먼저 묻습니다. (`skills/README.md` 참고)

고객 불만을 문구로 바꾸는 가장 직접적인 곳입니다. 단, **우리 제품이 사실로 답할 수 있는 것만** 약속합니다.

## 입력값
- `{out}/03_insights.md` (칭찬/불만 클러스터, 고객 언어, 기회, 포지셔닝 후보)
- `brand.md` (우리 제품 사실, 판매 언어, 가격대)

## 실행 절차

### STEP 1 - 포지셔닝 한 문장 선택
`{out}/03_insights.md` 맨 아래 **"선택된 포지셔닝"** 을 읽어 쓴다. 비어 있으면(단독 실행 포함) 후보를 보여 주고 **사용자가 고를 때까지 초안을 만들지 않는다.** 스킬이 대신 정하지 않는다.

### STEP 2 - 제목과 헤드라인
- **제품 제목 후보 3개** (검색 키워드와 고객 언어 포함, 길이 가이드: 60자 안팎)
- **헤드라인 3개 + 서브헤드 3개**
- 각각 어떤 고객 불만/언어에서 나왔는지 근거 번호를 적는다.

### STEP 3 - 핵심 불릿 5개
불릿마다: 영어 문구 / 한국어 해설 / 근거 / 우리 사실 확인 여부(`[사실]` `[공백]`).
**`[공백]`이 붙은 불릿은 "확인 후 사용"으로 표시한다.** (예: 임상 수치, 무향, 알레르겐 프리)

### STEP 4 - 섹션 구성 (위에서 아래 순서)
히어로 -> 문제 공감(고객 언어) -> 우리의 답(사실만) -> 성분 투명성 -> 사용법과 패치 테스트 안내 -> 리뷰 -> FAQ -> 배송, 반품.
섹션마다 목적 한 줄과 들어갈 문구 초안. 경쟁사에서 반복적으로 나온 **불만에 답하는 섹션**(예: 첫 사용 가이드, 포장·사용 방법)을 표시한다.

### STEP 5 - 이미지 컷 리스트 (8컷)
컷마다: 목적 / 구도 / 화면 텍스트(자막) / 필요한 소품 / 주의(효능 시연은 증빙 필요). 첫 3컷이 가장 중요하다고 표시한다.

### STEP 6 - FAQ 5~8개
03의 질문형 키워드와 고객이 실제로 묻는 질문에서 만든다. 답은 **직접 답을 첫 문장에**, 모르는 사실은 `[공백]`.

### STEP 7 - SEO 메타
타이틀 태그(60자 안팎) 2안, 메타 설명(155자 안팎) 2안, 이미지 대체 텍스트 예시 3개.

## 산출물
**`{out}/04_pdp_draft.md`** - 위 7단계. 영어 문구(미국 게재용)와 한국어 해설 병기. 파일 하단에 `claims-check`로 넘길 **문구 목록**.

## 핸드오프
- <- `insight-synthesis`
- -> `claims-check`: 모든 영어 문구
- -> `geo-qa-outline`: FAQ와 섹션 구성

## 작성 원칙
- **경쟁사 문구를 복사하거나 살짝 바꿔 쓰지 않는다.** 고객 언어와 우리 사실로 새로 쓴다.
- 우리 제품 사실이 없으면 효능, 수치, 임상, 인증 문구를 쓰지 않는다. 자리만 만들고 `[공백]`으로 둔다.
- 과장 형용사(best, miracle, perfect)를 피하고, 구체적인 사용 장면과 조건을 쓴다.
- 초안일 뿐이다. 최종 문구는 사람이 확정하고 `claims-check`를 거친다.
