# geo-qa-outline - GEO Q&A와 블로그 아웃라인 (07번 파일, 선택)

> `{out}` = 이번 프로젝트의 결과 폴더 `outputs/<제품명>_<날짜>/` 입니다. 단독 실행할 때는 가장 최근 폴더를 쓰고, 둘 이상이라 모호하면 먼저 묻습니다. (`skills/README.md` 참고)

같은 리서치로 **검색과 AI 답변에서 인용되기 쉬운 형태**의 글을 기획합니다. 노출을 약속하는 스킬이 아니라, 질문-답변 구조를 잘 만드는 스킬입니다.

## 입력값
- `{out}/03_insights.md` (질문형 키워드, 고객 언어, 불만 클러스터)
- `{out}/04_pdp_draft.md` (FAQ, 섹션 구성), `brand.md`

## 실행 절차

### STEP 1 - 고객 질문 12~15개
고객이 리뷰, 질문 섹션에서 실제로 묻거나 걱정한 것을 질문형 문장으로 만든다. 의도별 분류: 증상형 / 비교형 / 사용법형 / 안전형 / 구매형.

### STEP 2 - 답변 초안 (질문마다)
- **첫 문장에 직접 답**한다(한 문장). 이어서 조건, 예외, 확인 방법을 2~3문장.
- 사실은 `[사실]`, 우리 제품 정보가 없으면 `[공백]`으로 두고 일반 정보와 구분한다.
- 의학적 판단이 필요한 질문(질환, 알레르기)은 "전문가와 상담"을 안내하고 **치료 효능을 말하지 않는다.**

### STEP 3 - 블로그 아웃라인 1편
- 제목 후보 3개, 도입(고객 상황 한 문단), H2 5~7개(질문형 H2 포함), 마무리와 다음 행동
- 각 H2 아래 들어갈 근거(공식 자료, 우리 사실)와 내부 링크 위치(상품 페이지)

### STEP 4 - 구조와 점검
- 질문-답변이 한 화면에서 한 덩어리로 읽히는지, 표나 목록이 필요한 곳은 어디인지
- FAQ는 **가독성과 AI 답변 인용 가능성**을 위한 구조이지, 검색결과의 특별한 노출을 보장하지 않는다(FAQ 리치 결과는 2026년에 종료된 것으로 확인된 바 있다. 사용 시점의 구글 공식 문서로 재확인).
- 경쟁사 문장을 복사하지 않는다.

## 산출물
**`{out}/07_geo_qa.md`** - 질문 목록 + 답변 초안 + 블로그 아웃라인 + 점검 메모

## 핸드오프
- <- `insight-synthesis`, `pdp-draft`
- -> `claims-check` (문구가 늘었으면 다시 점검)

## 작성 원칙
- 지어낸 통계, 출처 없는 연구 결과를 쓰지 않는다. 출처가 있는 것만, URL과 함께.
- 질문은 고객의 표현으로, 답은 사실과 조건으로. 마케팅 문구를 섞지 않는다.
