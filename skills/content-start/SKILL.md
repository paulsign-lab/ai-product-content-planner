# content-start - 콘텐츠 분석 시작 (입구 스킬)

"뭐부터 하지?"를 없앱니다. 진행 방식을 고르고, 질문에 답하면 **경쟁 제품 읽기 -> 리뷰 읽기 -> 인사이트 -> (사람이 포지셔닝 선택) -> 상세페이지 초안 -> 숏폼 3안 -> 주의 표현 점검**이 이어집니다.

> `{out}` = 이번 프로젝트의 결과 폴더 `outputs/<제품 슬러그>_<YYYYMMDD>/` (예: `outputs/moreday-lipbalm_20261120/`). 시작할 때 만들고, 모든 단계가 여기에 저장합니다. 다른 제품으로 다시 돌려도 이전 결과를 덮어쓰지 않습니다.

## 0. 시작 전 안내와 사전 점검 (먼저 사용자에게 보여 준다)

**안내 (4줄 이내로 그대로 전달):**
1. 처음부터 끝까지 보통 20~40분 안팎이 걸립니다 `[추정: 사이트 수와 응답 속도에 따라 달라짐]`. 브라우저 도구를 쓰는 02단계가 가장 오래 걸립니다.
2. 도중에 **허용 여부를 묻는 창**이 여러 번 뜹니다. 웹페이지를 읽는 작업이라 그렇습니다. "이 작업 폴더의 파일 저장"과 "공개 상품 페이지 읽기"만 허용하세요. 계정, 결제, 로그인 화면을 열자는 요청이 오면 허용하지 마세요.
3. 구독 사용량이 소모됩니다. 사용량이 걱정되면 경쟁사 3곳으로 시작하세요.
4. 결과는 내부 기획용입니다. 경쟁사 이름과 리뷰 인용을 외부에 올리지 마세요.

**사전 점검:**
- 브라우저 도구(Playwright MCP 또는 Claude in Chrome)가 연결되어 있는가? 없으면 **멈추지 말고** 02단계를 "붙여넣기 경로"로 진행한다고 안내한다 (`review-harvest` 참고). 설치를 먼저 하고 싶으면 `INSTALL.md` STEP 3을 안내한다.
- `outputs/` 폴더가 있는가? 없으면 만든다.

## 1. 진행 방식 선택 (질문 1개)

> **어떤 방식으로 진행할까요?**
> - **교육 모드 (처음이라면 권장):** 단계마다 "무엇을 하고, 왜 필요한지, 끝나고 무엇을 확인할지"를 설명하고, 확인하면 다음으로 넘어갑니다.
> - **빠른 모드:** 질문에 한 번 답하면 끝까지 자동으로 진행하고, 정지점에서만 멈춥니다.

사용자가 "교육 모드로", "천천히", "설명해 줘"라고 하면 교육 모드, 아무 말이 없으면 처음이라면 교육 모드를 권한다.
교육 모드의 단계별 설명 카드는 같은 폴더의 `education-mode.md`를 읽어서 쓴다.

## 2. 인테이크 - 세 덩어리로 묻는다
이미 `brand.md` / `competitors.md`가 있으면 먼저 읽고 **빈 칸만** 묻는다. **모든 질문에 예시를 붙이고, "모르면 모른다고 답하셔도 됩니다"를 첫머리에 말한다.**
- **빠른 모드:** 세 덩어리를 한 메시지에 묶어 보여 준다.
- **교육 모드:** 덩어리마다 따로 묻고, 답을 정리해서 확인받은 뒤 다음 덩어리로 간다.

### 덩어리 A. 브랜드와 시장
1. 브랜드 이름, 카테고리, 대표 제품 (예: "모어데이 / 립케어 / 비건 립 트리트먼트")
2. 가격대 (예: "14달러")
3. **진출 국가와 채널** (예: "미국, 쇼피파이 자사몰") - 06 주의 표현 점검의 기준이 된다
4. 판매 언어 (예: "영어")

### 덩어리 B. 우리 제품 사실 (가장 중요)
> "근거 있게 말할 수 있는 것만 적어 주세요. 없으면 '없음', 모르면 '모름'이라고 하면 됩니다. 비워 두는 것이 지어내는 것보다 낫습니다."
- 성분, 향, 텍스처, 용량 (예: "전성분표 있음, 무향인지는 모름")
- 임상/시험 자료 (기관, 지표, 기간) (예: "없음")
- 인증, 수상 (예: "비건 표기만, 인증기관 확인은 안 함")
- 자사 리뷰, 고객 인터뷰 (예: "없음, 신규 브랜드")

### 덩어리 C. 경쟁, 콘텐츠, 제약
1. **경쟁 제품 상품 페이지 URL 3~5개.** 브랜드 쪽이 직접 고르는 것이 가장 좋다.
   - URL을 모르면 **"경쟁사 찾기 도우미"**(아래)로 넘어간다. 홈페이지 주소만 알아도 된다.
2. **만들 콘텐츠:** 상세페이지 / 숏폼 / GEO Q&A 중 무엇 (예: "상세페이지와 숏폼")
3. **제약:** 규제, 판매 지역, 모브랜드, 금지 표현
4. **써도 되는지 궁금한 표현** (예: "'기능성', '치료' 같은 말을 써도 되나요?") - `claims-check`에서 우선 다룬다

- 답이 "없음/모름"이면 **그대로 `[공백]`으로 기록**하고 지어내지 않는다.
- `templates/brand.md.template`, `competitors.md.template` 양식으로 작업 폴더에 `brand.md`, `competitors.md`를 만든다(모르는 칸은 `TBD`). 만든 뒤 요약해서 사용자에게 확인받는다.

## 2-1. 경쟁사 찾기 도우미 (URL이 없을 때)
1. 사용자의 카테고리, 대표 제품, 진출 국가로 웹 검색을 한다. (예: 국가를 미국으로 두고 "<제품 종류> serum for sensitive skin" 같은 영어 검색어 3~4개)
2. 검색 결과에서 **브랜드 자사몰의 상품 페이지**만 후보로 모은다. 블로그, 쇼핑몰 입점 페이지, 광고성 비교 글은 제외한다.
3. **후보 5~8개**를 표로 보여 준다: 브랜드 / 상품 URL / 가격대 / 왜 경쟁인가(한 줄) / 리뷰가 보이는가.
4. **사용자가 3~5개를 고른다.** 사용자가 고르지 않으면 진행하지 않는다. 결과에 `자동 선정(검증 필요)`을 표시한다.
5. 사용자가 직접 찾고 싶어 하면 이렇게 안내한다: 구글에서 국가를 미국으로 설정하고 검색 -> 1페이지의 자사몰 확인 -> 가격대와 타깃이 비슷한 곳 -> 상품 페이지에 리뷰가 있는 곳.

## 3. 실행 절차

| STEP | 스킬 | 입력 | 산출물 |
|---|---|---|---|
| 1 | `site-scan` | competitors.md, brand.md | `{out}/01_site_scan.md` |
| 2 | `review-harvest` | 01, competitors.md | `{out}/02_reviews.md` |
| 3 | `insight-synthesis` | 01, 02, brand.md | `{out}/03_insights.md` |
| **정지** | **포지셔닝 선택** | 03의 후보 2~3개 | 03 파일 맨 아래 "선택된 포지셔닝" |
| 4 | `pdp-draft` | 03, brand.md | `{out}/04_pdp_draft.md` |
| 5 | `shortform-draft` | 03, brand.md | `{out}/05_shortform.md` |
| 6 | `claims-check` | 04, 05, brand.md, 국가와 카테고리 | `{out}/06_claims_check.md` |
| 7 | `geo-qa-outline` (선택) | 03, 04 | `{out}/07_geo_qa.md` |

### 정지점 (두 모드 공통, 이 경우에는 반드시 멈춘다)
1. **03 완료 후 포지셔닝 선택.** 후보를 보여 주고 사용자가 고를 때까지 04로 넘어가지 않는다. (스킬이 대신 고르지 않는다) 선택 결과는 `{out}/03_insights.md` 맨 아래 "선택된 포지셔닝"에 기록한다. 마음에 드는 것이 없으면 직접 쓰게 한다.
2. 접근에 성공한 경쟁사가 **절반 미만**일 때 (붙여넣기 경로로 갈지, 경쟁사를 바꿀지 묻는다)
3. 인테이크에 없던 결정이 필요해 결과가 크게 갈릴 때
4. 사용자가 중단을 요청할 때

### 빠른 모드의 진행 규칙
- 단계 사이에는 한 줄만 보고하고 바로 다음으로 간다. (예: "02 완료: 3곳 중 2곳 성공, 총 28건(5점 14, 1~3점 12). 03으로 넘어갑니다.")
- 접근 실패나 저별점 읽기 실패가 있으면 그 한 줄에 **반드시** 포함한다. (예: "1곳 접근 차단, 저별점 읽기 실패 1곳. 불만 근거가 얇습니다.")

### 교육 모드의 진행 규칙
- 각 단계 **시작 전** `education-mode.md`의 카드(무엇을 / 왜 / 이 단계에서 확인할 것 / 흔한 실수)를 보여 준다.
- **끝난 뒤** 결과를 5줄 이내로 요약하고 "확인 포인트"를 짚어 준다.
- 그리고 묻는다: **"다음 단계로 갈까요? (예 / 이 단계 다시 / 더 설명)"** 사용자가 "예"라고 하기 전에 넘어가지 않는다.
- 설명은 쉬운 말로, 전문 용어는 처음 나올 때 풀어 쓴다.

### 공통
- 다음 단계의 입력은 앞 산출물에서 그대로 읽는다(다시 묻지 않는다).
- 경쟁 제품 페이지 읽기(01)는 병렬로 해도 되지만, **리뷰 수집(02)은 사이트마다 순서대로** 한다(`skills/README.md`의 예절 규칙).

## 4. 마무리 보고
1. **확정된 것(사실)** 2. **아직 가설인 것** 3. **비어 있는 것(공백)**
이어서 **다음에 할 일 (우선순위):**
1. `[공백]`부터 채우기 (제품 사실, 증빙). 채운 뒤 03 -> 04 -> 05 -> 06을 다시 실행
2. 06의 위험도 중간 이상 문구를 대안 문구로 교체
3. 05에서 촬영할 안 하나 고르기
- 결과 폴더 위치를 알려 준다: `{out}`
- "`USAGE.md`에 단계별 활용법이 있습니다"라고 알린다.
- 한 줄 고지: "`outputs/`는 내부 기획용입니다. 경쟁사 이름과 리뷰 인용을 외부에 게시하지 마세요."
- "`자동 선정(검증 필요)`으로 표시된 제품이 있으면 알려 주세요. 해당 사이트만 다시 읽어 반영합니다."

## 작성 원칙
- 데이터가 없어도 시작한다. 가설은 가설이라고 표시한다.
- 사용자가 모르는 것을 물어서 멈추기보다 `[공백]`으로 기록하고 다음 단계로 넘긴다. 단, 위 정지점은 예외다.
- AI는 공개 자료를 구조화하고 초안을 쓸 뿐, **포지셔닝과 최종 문구의 결정은 사람의 몫**이다.
