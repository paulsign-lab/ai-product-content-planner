# 스킬 흐름 안내

## 처음이라면
```
콘텐츠 분석 시작하자
```
`content-start`가 진행 방식(교육 모드 / 빠른 모드)을 묻고, 인테이크(브랜드와 시장 / 제품 사실 / 경쟁과 콘텐츠)를 받은 뒤 01~07 파일을 만듭니다. **03 뒤의 포지셔닝 선택은 언제나 사람이 합니다.**

## 데이터 핸드오프 체인

```
brand.md / competitors.md (인테이크)
        |
   [01 site-scan]  --- 경쟁 제품 페이지: 메시지, 가격 표기, 성분 / 임상 주장
        |
   [02 review-harvest] --- 리뷰: 별점별 샘플, 짧은 인용, 수집 로그 (브라우저)
        |
   [03 insight-synthesis] --- 소구점 / 불만 / 고객 언어 / 갭 / 기회
        |
   ** 사람이 포지셔닝 선택 ** (03 맨 아래 기록)
        |
   +----+-----------+------------------+
   |                |                  |
 [04 pdp-draft]  [05 shortform-draft]  [07 geo-qa-outline] (선택)
   |                |
   +-------+--------+
           |
     [06 claims-check] --- 04, 05의 문구를 미국 화장품 기준으로 점검
```
앞 스킬의 출력이 뒤 스킬의 입력이 됩니다. 각 스킬은 단독으로도 실행할 수 있습니다.

## 스킬 목록

| 스킬 | 하는 일 | 산출물 | 필요 도구 |
|---|---|---|---|
| `content-start` | 입구. 모드 선택, 인테이크, 경쟁사 찾기 도우미, 01~07 진행 | brand.md, competitors.md | 없음 |
| `site-scan` | 경쟁 제품 페이지의 메시지, 가격 표기, 주장 | `01_site_scan.md` | 일반 웹 조회 |
| `review-harvest` | 리뷰 수집, 별점별 샘플링, 수집 로그 | `02_reviews.md` | 브라우저(Playwright 또는 Claude in Chrome). **없으면 붙여넣기 경로** |
| `insight-synthesis` | 소구점, 불만, 고객 언어, 갭, 기회 | `03_insights.md` | 없음 |
| `pdp-draft` | 상세페이지 초안 | `04_pdp_draft.md` | 없음 |
| `shortform-draft` | 숏폼 3안 기획과 스크립트 | `05_shortform.md` | 없음 |
| `claims-check` | 주의 표현 점검 (미국 x 화장품은 상세, 그 외는 일반 점검과 전문가 확인 질문) | `06_claims_check.md` | 없음 |
| `geo-qa-outline` | (선택) 블로그 아웃라인, GEO Q&A | `07_geo_qa.md` | 없음 |

## 공통 규칙 (모든 스킬에 적용)

### 결과 폴더 `{out}`
- 프로젝트마다 `outputs/<제품 슬러그>_<YYYYMMDD>/` 폴더를 만들고 01~07을 그 안에 저장한다. (예: `outputs/moreday-lipbalm_20261120/`) 이전 결과를 덮어쓰지 않는다.
- 스킬을 **단독 실행**할 때는 가장 최근 폴더를 쓴다. 폴더가 둘 이상이라 어느 것인지 모호하면 먼저 묻는다.

### 정지점 (자동 진행 중에도 반드시 멈춘다)
1. 03 완료 후 **포지셔닝 선택** (스킬이 대신 고르지 않는다)
2. 접근에 성공한 경쟁사가 절반 미만일 때
3. 인테이크에 없던 결정이 필요해 결과가 크게 갈릴 때
4. 사용자가 중단을 요청할 때

### 진행 모드
- **교육 모드:** 단계마다 설명 카드(`content-start/education-mode.md`)를 보여 주고 확인 후 진행
- **빠른 모드:** 정지점에서만 멈추고 단계 사이에는 한 줄 보고

### 도구 규칙: 일반 웹 조회가 기본, 리뷰만 브라우저
- 홈페이지, 상품 기본 정보는 **일반 웹 조회(WebFetch)** 로 읽습니다. 빠르고 가볍습니다.
- **리뷰는 브라우저 도구로만** 읽습니다. 리뷰는 페이지가 열린 뒤 뜨는 위젯이라 일반 웹 조회로는 보이지 않습니다.
- URL을 추측하지 않습니다. 페이지의 링크(href)에서 찾은 주소만 씁니다.
- 접근 실패는 지우지 말고 `ACCESS FAILED: URL, 이유`로 기록하고 해당 항목은 `미확인`으로 둡니다.

### 증거 라벨 (모든 산출물에 붙입니다)
| 라벨 | 뜻 |
|---|---|
| `[사실]` | 페이지에서 읽었거나 사용자가 확인해 준 것 (출처 URL 병기) |
| `[가설]` | 근거가 부족하거나 한 걸음 더 추론한 것 |
| `[공백]` | 필요하지만 확보하지 못한 것. 채우지 않고 비워 둔다 |
| `[추정]` | 읽은 글을 바탕으로 어림한 값 |

> **없는 수치, 인용, 고객 반응, 우리 제품의 효능을 만들어 내지 않는다.** 빈곳을 "비어 있다"고 정확히 적는 것이 완성도 높은 산출물입니다.

### 리뷰 수집 예절 (review-harvest가 반드시 지킨다)
1. 로그인하지 않은 상태, 공개 페이지만. 로그인벽, 캡차가 나오면 멈추고 기록한다. 우회하지 않는다.
2. 사이트당 상품 1개, 상품당 리뷰 최대 30건. 사람이 읽는 속도로 순서대로 처리한다(페이지 사이에 2~3초 이상 쉰다).
3. 리뷰어 이름, 사진, 프로필은 수집하지 않는다. 별점, 날짜, 본문만 쓴다.
4. 인용은 약 125자 이내로 짧게, 출처 URL과 함께. 경쟁사 문구를 우리 콘텐츠에 복사하지 않는다.
5. 약관이 자동 수집을 제한할 수 있다는 점을 산출물 상단에 적는다. 확인과 책임은 사용자에게 있다.

### 결과물 취급
- `outputs/`는 **내부 기획용**이다. 경쟁사 이름, 리뷰 원문 인용을 외부에 게시하거나 공개 저장소에 올리지 않는다.
- 수강, 교육 자료나 공개 예시를 만들 때는 경쟁사를 익명(A, B, C)으로 바꾸고 인용 원문과 URL을 빼고 요지만 남긴다.

### 표본 한계 (산출물 상단에 반드시 적는다)
- 기본 화면의 리뷰는 대부분 높은 별점이다. **별점별로 따로 읽는다.** (낮은 별점 정렬이 있으면 사용)
- 읽은 건수는 전체 리뷰 수와 다르다. 통계가 아니라 **관찰된 경향**으로만 쓴다.
- 체험단, 무료 제공, 다른 제품 리뷰가 섞일 수 있다. 발견하면 표시한다.
